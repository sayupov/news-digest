# NEWS & EVENTS INTELLIGENCE 2.0

RSS/Atom → Python → Gemini → Telegram. Запуск по расписанию GitHub Actions. Сервер не требуется.

## Установка

1. Загрузите `digest.py`, `config.json`, `tests/test_digest.py` и `.github/workflows/digest.yml` в корень своего GitHub-репозитория, сохраняя вложенные папки. Важно: **workflow — именно `.github/workflows/digest.yml`, не `digest.yml.txt`**.
2. В GitHub откройте Settings → Secrets and variables → Actions → New repository secret. Создайте `GEMINI_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
3. Если нужно выбрать другую поддерживаемую модель, создайте Repository variable `GEMINI_MODEL` в Settings → Secrets and variables → Actions → Variables. По умолчанию используется `gemini-3.8-flash`. Доступность/квоты зависят от вашего аккаунта Gemini API.
4. В Settings → Actions → General → Workflow permissions установите **Read and write permissions**, иначе история `state.json` не сможет сохраняться. Если это запрещено политикой организации, сохранение истории необходимо организовать другим способом.
5. Убедитесь, что Actions включены и workflow находится в **default branch**. Откройте Actions → News & Events Intelligence → Run workflow → news. Проверьте логи и Telegram.
6. По расписанию: ежедневно 03:00 UTC = 08:00 Asia/Oral; воскресенье 12:00 UTC = 17:00 Asia/Oral. GitHub может задерживать запуск по расписанию; это не точный таймер.

## Тестирование локально

```bash
python -m unittest discover -s tests -v
DRY_RUN=1 python digest.py news
```

`DRY_RUN=1` показывает входной промпт, **не обращается к Gemini и не отправляет сообщение**. Требуется интернет для получения RSS. Не публикуйте содержимое секретов или токены.

## Источники и мероприятия

Список в `config.json`. Недоступный RSS Google DeepMind заменён дополнительными источниками; адрес можно вернуть, когда он начнёт стабильно отдавать валидный XML. `events_feeds` по-прежнему пуст: **поиск мероприятий пока не реализован**. Добавлять произвольные веб-страницы вместо RSS нельзя — сначала нужен проверенный RSS/Atom-источник или отдельный адаптер. Дата публикации объявления не равна дате мероприятия; система помечает такие записи как анонсы, но не подтверждает дату события.

## Ограничения

- Анализ выполняется **по аннотациям RSS**, а не по полным статьям. Независимая фактологическая проверка не реализована.
- История хранится в `state.json` и коммитится после успешного ежедневного отчёта. В публичном репозитории заголовки/URL истории будут видны другим; используйте приватный репозиторий при необходимости.
- Еженедельный отчёт рассматривает окно за 7 дней, включая материалы, уже вошедшие в ежедневные отчёты. Это задумано.
- При частичном успехе отправки нескольких сообщений Telegram и последующем сбое возможна повторная отправка при следующем запуске. Гарантии exactly-once нет.
- При перебоях RSS, Gemini, превышении лимитов Gemini или изменениях API отчёт может не сформироваться; смотрите Actions logs.
- Workflow автоматически делает `git push` изменений `state.json`, что может конфликтовать с одновременной записью в default branch; настроен concurrency, но внешние изменения всё равно возможны.
- Реальная интеграция с Gemini и Telegram должна быть проверена после настройки секретов.
